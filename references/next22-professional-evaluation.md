# NEXT-2.2 专业指导配对评估

日期：2026-10-27（Asia/Shanghai）
固定基线：`4e9271870ce4abd16720fc7f49b530eebd52f567`
评估对象：NEXT-2.2 本地候选中的知识规则、RuleContextV4、RuleApplicationV4、GuidanceOutputV4 与 GuidanceReceiptV4。

## 结论

八组配对、16 份脱敏合成输出全部通过最终独立语义审核。每份输出都保存并校验了实际规则上下文、应用检查、完整指导正文、目标/用途、行动、理由、观察方法、缺口、保持不改理由（适用时），以及与独立审核结果完全一致的精确 hash 绑定。

这证明的是 Gate B 合成专业样例和工程绑定通过，不证明真实账号效果、Chrome 私有采集或增长结果。测试未使用真实账号资料，仓库中没有私有证据原件。

## 方法

- 每组只改变表中一个关键因素；共同主题、正文或累计值保持不变。
- 真实调用 `loadKnowledgeCatalog`、`buildRuleContextV4`、`validateRuleApplication`、`validateGuidanceOutput` 和 `validateGuidanceReceipt`，不是另写一套规则计算器。
- 每份候选由明确的 OperationalRuleV4 选择结果驱动；语义检查绑定实际输入 hash，完整正文绑定输出 hash。
- 候选由子代理起草，主线程另作语义复核；测试中的不同 `generator_ref` 是审核绑定 fixture，本身不能证明独立评审发生。审核逐项检查数据正确、来源边界、用户目标、可执行性、保留原意、通俗表达、投入合理和观察方法。
- 任何一项失败都会保存 `revision_required` 和具体 issue；最终样例不得靠平均分抵消关键否决。

## B15–B17 只读复核

- B15：内容审核保存前会把实际结果中的 `decision/checks/issues` 与提交回执逐项精确比较；实际否决不能被另一个批准 payload 覆盖。
- B16：pack readiness 会比较当前 draft 的 `personal_context_selection_hash`；正文不变而个人依据变化时，旧 pack 不再保持 ready。
- B17：`resume` 对已有 active pack 重新进入 `finalizeContent` 并消费当前 readiness；缺失资产会给出具体未满足项，不沿用历史 ready。
- 本轮静态复核未发现新的确定性缺陷；这不是 B15–B17 全链 CLI 或真实资产验收替代品。

## 主线程的独立复核与修订

主线程逐项阅读了16份动作、理由、观察和缺口，要求修正三处：没有实测材料时不得把夸大标题改成虚构的“三次实测”；24h/72h例子必须明确预先固定72h窗口；标签报告配对只改变实际警示，不能同时改变敏感程度和证据质量。增长例子也改为仅使用实际取得的指标。上述修订已进入最终样例，初始问题与修订理由保留在私有评审记录。

完整RuleContext/Application/Output及绑定fixture仅在显式指定私有XOPS_EVAL_ARTIFACT_DIR时写出，常规CI不写账号目录。不同reviewer字符串仅用于合同断言；实际独立语义复核另有记录。

知识时间勘误后，16份完整用户可见输出的content hash均未变化，复用原独立语义判断；当前规则/材料指纹与回执绑定另行确定性校验，未把改变绑定的fixture假称为新的真人审核。
